# MySQL 自动迁移约定

- 每次发布数据库变更前，必须先提升 `application.yml` 中的 `order.migration-version`；`order.version` 是对外展示版本，不作为数据库迁移门禁。
- 新迁移只允许追加，文件名使用 `VYYYY_MM_DD_NN__description.sql`。
- 已在任何环境执行过的迁移脚本禁止修改、重命名或删除，否则 checksum 校验会阻止启动。
- Flyway 只扫描本目录；仓库根目录的 `sql/` 不会被自动执行。
- 迁移失败后禁止自动 `repair`。先定位并人工处置失败原因，再按发布流程恢复。
- 空库不能由增量脚本自动初始化，必须先导入经过审核的 `sql/init/order_base_20260803.sql` 受控基线快照；legacy 结构指纹仍取自该 08-03 快照。只有全部 69 张快照表、关键列和主键结构完整且没有历史表时，应用才会采用保守兼容边界 baseline 到 `2026.08.17.0`，08-04/08-08 的历史效果由后续 successor 策略处理。
- `V2026_08_04_00`、`V2026_08_08_00` 必须保留，用于校验已经执行过这些迁移的历史环境；新的无历史 legacy 库不会自动重放它们。
- `V2026_08_18_04` 是不修改 legacy 任务和部门数据的兼容 marker；`V2026_08_18_05` 只幂等补齐缺失的敏感权限及角色关联。两份兼容 successor 一旦执行同样禁止修改或删除。

## 2026-11-08 个人产品匹配比例

- 发布门禁号提升至 `order.migration-version: 1.2.4`，新增 `V2026_11_08_00__member_product_match_ratios.sql`；先完成数据库迁移，再放行使用新列的后台查询和接单请求。
- 迁移仅为 `order_user` 增加可空的 `product_match_min`、`product_match_max`，不回填会员等级比例，不改历史产品匹配开关。两列都为空的历史启用会员仍沿用全局匹配规则。
- 个人开关继续使用 `0=启用、1=禁用`。显式启用或修改比例须满足 `0 < 最小比例 <= 最大比例 <= 100`；仅修改其他会员资料时兼容历史空比例。禁用可保留空值或 `0/0`。
- 新代码已经读取这两列，不能在未迁移的库上直接启动后关闭迁移。回退旧应用时可保留新增列，无需删除列。
